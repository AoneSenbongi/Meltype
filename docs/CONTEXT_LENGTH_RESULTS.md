# 長文での文脈評価の現状測定

2026年10月15日。実行先はexperimental-build/context-length-20261015-163834。実zenz-v3.2-small Q5_K_M、CPU4スレッド、azooKey/llama.cpp b4846、context1024で測定した。製品の100文字上限・候補長・生成上限・期限は変更していない。PCへの適用・公開も行っていない。

## 結論

100文字上限を単純に増やす変更では長文対応にならない。現状は全文を候補として生成し直すため、出力が長いほど応答に時間がかかる。上限を通さない診断でも200/250文字は1500msで期限切れになった。次の設計候補は、前後の文章を判断材料にし、生成する出力を対象文節へ限定する方式。対象を複数回評価して必要な箇所を更新する場合も、古い結果・手動選択・確定済み文章を保護し、実測で判断する。この設計は未実装。

## 範囲とデータ

8種類の意味例（橋/箸、川/革、暑い/厚い、科学/化学）を使用。候補・読み・正解は手作業で作成し、途中の説明部分は共通のひらがな文を繰り返す。実Google候補・日常の長文入力・人間の使用感を再現したデータではない。候補の正解率を製品全体の精度として解釈できない。

同じ読みを20/50/80/100/101/200/400文字へ伸ばし、50文字の後ろに意味が分かる手掛かりを置いた56段階。手掛かりがまだ完成していない20/50文字は採点しない。左文脈の手掛かりの後ろに0/64/128/256/400文字を挟んだ40例、複数誤りの正解全体を候補に含めない3例、長さの状態機械だけを通さない診断24例を合わせて123段階。

samples.jsonlとresults.jsonの全行一致、123件のID一意性、読みの文字数、候補内正解の有無、採用結果が候補内であること、101文字以降の本来の経路では要求0件であることをanalyze_length_results.pyで検証した。summary.jsonへ再集計している。

各段階のモデル測定は新しいContextEvaluationを使う。段階間の既採用表示の保持はこの集計に含めず、別の実controller試験で検証した。したがって101文字以降の基準候補への戻りを、実際の画面の揺れとして数えてはいけない。

## 後続の意味手掛かりと長さ

| 未確定の読み | 評価・採用 | 正解 | モデル応答の中央値 | 待機込みの中央値 |
| --- | ---: | ---: | ---: | ---: |
| 20文字 | 8/8 | 意味未確定につき未採点 | 197ms | 395ms |
| 50文字 | 8/8 | 意味未確定につき未採点 | 314ms | 508ms |
| 80文字 | 8/8 | 6/8 | 489ms | 688ms |
| 100文字 | 8/8 | 6/8 | 580ms | 774ms |
| 101/200/400文字 | 各0/8 | LLM精度は未測定 | 要求なし | 評価省略 |

80/100文字の基準候補は4/8正解。モデルは3例を改善した一方、革であるべき1例を川へ変えて悪化させ、合計6/8となった。厚い本の例も暑いのまま誤った。後半の手掛かりが役立つ例と、手掛かりがあっても誤る例の両方があった。80→100文字の間には対象語の選択変更はなかった。これは8系列の限定的な観測で、一般的な表示安定性の保証ではない。

実controllerの隔離試験では、100文字までに採用した接頭部は101文字へ伸ばしても保持されたが、新しいモデル要求は行われなかった。Enterで表示どおりの文章を確定した。100文字を超えると必ず表示が元に戻る、という動作ではない。テストでは入力変換器と評価器を固定した代役にしており、実アプリと実Google候補の試験ではない。

## 確定済み文章からの手掛かり

| 手掛かりの後ろに挟む文字数 | 正解 |
| --- | ---: |
| 0 | 5/8 |
| 64 | 6/8 |
| 128 | 4/8 |
| 256 | 4/8 |
| 400 | 4/8 |

左文脈は末尾128文字だけを送るため、128文字以上の挿入で手掛かりがpromptから完全に外れた。範囲内でも必ず正解するわけではない。短い繰返し文のどの位置で切れるかも変わるため、0→64の差を一般的な長さ効果とは扱わない。400文字挿入時に応答が速くなった値も、同じ末尾promptのキャッシュ等の影響を含み、長文ほど高速になるという意味ではない。

## 上限を通さない診断

状態機械の100文字上限だけを通さず、同じevaluatorへ渡した。製品での動作ではない。

| 読み | 結果 |
| --- | --- |
| 200文字 | 8/8が1500msの期限切れ。採用0件 |
| 250文字 | 8/8が1500msの期限切れ。採用0件 |
| 400文字 | 候補256文字上限により8/8がHTTP送信前に棄却 |

期限切れでは最終出力が取得できないため、モデルが意味を正しく判断できたかは未評価。192 tokenの出力上限や、さらに長い期限の結果をこの実験で切り分けてはいない。evaluator呼出しと実HTTP要求を同一視しない。

2箇所とも変更すべき正解全体が候補にない条件は、50/80/100文字の3例とも正解できなかった。これは候補生成の構造上の制限であり、モデルの意味判断の誤りとは分ける。

通常経路の75回の評価は全て候補内応答、例外0件。別群の診断では16回の期限切れ、8回の送信前棄却を記録した。モデルサーバーは実験終了時まで稼働しており、今回の失敗はserver異常終了ではない。
