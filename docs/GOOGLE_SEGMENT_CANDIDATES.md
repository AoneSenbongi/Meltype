# 手動でまとめた文節のGoogle候補取得

2026年10月18日。利用者は「にだい」単独で「荷台」が候補に出ず、変換区切りを変更しても選べないと報告した。導入版2.0.1-rc.6の実Google連携で、通常変換が「に｜だい」になり、Candidates("にだい")が空になることを確認した。学習を無効にした別セッションでGoogleへShift+Rightを2回送ると、1文節の「にだい」になり「荷台」が候補に含まれる。

通常変換の文節分割は維持する。選択中の文節に対する候補照会で、Googleが読みを複数文節へ分けて候補を返せない場合のみ、別セッションで先頭文節を読み全体へ伸ばして候補を取得する。「荷台」の固定追加や辞書への自動登録は行わない。読み全体の一致と1文節であることを検証し、境界が伸びない場合、失敗、時間切れ、100文字を超える読みには不完全な候補を返さない。セッションの破棄と既存の学習禁止を維持する。

再現テストでは通常の「に｜だい」を維持しつつ、明示的なCandidates("にだい")に「荷台」が含まれること、取得失敗、境界が伸びない応答、読み違い、既存の単文節候補を検証する。実Googleとキーボード制御で、区切り変更後の候補選択と後続文節の保持も確認する。PCへ適用する候補番号は2.0.1-rc.7とし、既存の辞書・設定を退避して標準更新手順を使う。

検証結果: 再現試験は修正前に失敗し、Google関連16/16と実Googleによる候補取得・区切り変更・選択・確定が通過。後続文節の保持は、英語判定の影響を避けるため既知の読みを持つ再変換で確認した。標準パッケージのNative18/18、Microsoft2/2、Google16/16と既存の実TSF試験が通過した。

2026年10月18日16:39JSTに2.0.1-rc.7を適用。配布ファイルの変更はMeltype.dllの1点だけ。導入済みbrokerへのprivate接続で、nidaiの入力、Space、Shift押下、Right2回、Shift解放、荷台の選択、Enterによる荷台の確定を確認した。学習は禁止した。manifest7/7、退避11/11、設定等3/3、brokerのジョブ外稼働とモデルhealth okを確認。詳細はexperimental-build/nidai-applied.json。

導入前のnidai-installed-before.logは試験側がShift本体の押下を送っていなかったため、区切り変更の再現証跡には使わない。導入後は押下・解放を含む正しいキー列で検証した。元のバグの再現証跡はnidai-red.logと、実Googleのnidai-direct.logおよびnidai-segment.logを用いる。
