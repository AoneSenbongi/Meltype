## 結論

未確定の読み全体をzenzで評価し、既存候補を選び直す試作が動いた。実Google候補では「川で靴を作る」を「革で靴を作る」、「GitHubの使用を確認します」を「GitHubの仕様を確認します」へ修正できた。

履歴を読みだけで再利用してモデル判断より優先する方式は、今回の別文脈テストでは悪化した。まず毎回の文脈評価を基準にし、学習による上書きは別途検証すべきと判断する。LLM本体の重みを追加訓練した結果ではない。

## 学習方式の比較

同音異義語の難例を意図的に用意した対照実験。学習用10イベントを20周し、左文脈・右文脈・読みが学習例と完全一致しない26例で比較した。候補と正解は手作業で定義した。実Google候補での精度や日常の正解率を表す数字ではない。

| 方式 | 正解 | 元の正解を崩した数 | 履歴再利用 |
| --- | ---: | ---: | ---: |
| 基準候補をそのまま使う | 5/26 | 0 | 0 |
| LLMで毎回評価、追加履歴なし | 23/26 | 0 | 0 |

文脈別方式は今回の評価で履歴を一度も再利用していない。LLM単独と同じ数字なのはこのためであり、個人最適化の効果を実証した結果ではない。また、LLMなしの候補は意図的に誤りを含むため、23/26と5/26の差を製品全体の改善幅として扱えない。

LLM単独の失敗3例は「千ページの本」の文脈で厚い→暑い、「野菜と果物」の文脈で青果→成果、候補に生花を含めなかった例で生花を出せない、だった。26例中25例に正解候補を含め、うち23例を選べた。文脈評価と候補生成範囲はそれぞれ改善が必要。
