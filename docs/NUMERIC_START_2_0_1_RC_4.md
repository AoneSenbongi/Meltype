# 数字から始まる未確定入力

利用者は1.5baisokuを「1.5倍速」に変換したいが、英字のままになり、先頭の1には未確定の下線が付かないと報告した。Windows Nativeのキー受付は未確定入力のない状態で数字キーを対象にしていなかった。先頭の1はアプリへ直接入り、その後の.から別の未確定入力が始まる。

修正前に実TSFキーイベントとアプリ側の直接入力を再現し、1.5baisokuが英字のまま確定することを確認した。内部brokerへ全文を渡す試験では1.5倍速に変換できたため、その試験だけではこの不具合を検出できなかった。

自動モードでは上段の数字キーとテンキーも未確定入力を開始する。先頭の1から未確定範囲に含め、小数の半角数字と小数点を保ちながら後続の日本語を変換する。英語モード、保護欄の扱いは維持する。数字だけの入力、小数、日本語の単位、英語モードを実TSFで確認する。PC適用版は2.0.1-rc.4。公開しない。

## 検証範囲

実TSFとアプリの直接入力を含め、整数・小数・末尾ゼロ・3桁の小数・桁区切り・負数・倍速/倍/秒/時間/円/キロ/メートル・cm/kg・数字のみ・IP・バージョン・ファイル名の26例を検証した。同じ26例は明示英語モードで原文保持を確認し、テンキー4例と日英文脈2例、数字単独のSpace候補、最初の数字の未確定状態も確認した。独立例はモード切替で接続を作り直し、前ケースの確定状態を持ち越さない。rc.4の製品修正はNativeの数字キー受付で、特定語の置換や例外辞書は追加していない。標準パッケージ一式は通過。2026年10月15日23:03JSTに2.0.1-rc.4をPCへ適用し、配置7/7・登録・broker/modelの稼働とhealthを確認した。導入brokerでも1.5baisokuと0.75baiの変換を即時・モデル待機後に確認。100enはEnterで末尾nを確定した場合、100ennは打鍵直後とモデル待機後に100円へ変換できた。英語モードとローマ字補助非表示も維持。実アプリの開き直し後の手入力確認は利用者に依頼する。
