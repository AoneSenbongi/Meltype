# 候補欄のサイズ更新漏れ（2.0.1-rc.6）

2026年10月17日。利用者は候補一覧の下側が見切れると報告した。発生したアプリと再現操作は不明。調査では、候補データ更新後にGetTextExtが失敗すると配置とサイズ更新を行わず、以前の小さい候補欄に新しい候補を描く経路が見つかった。隔離試験で1件分の表示領域30pxに9件分の内容220pxを描く状態を確認した。報告された実アプリで同じ経路を通ったかは未確認。

入力位置を一時的に取得できないときは、同じ変換中に最後に取得できた位置で候補欄のサイズと上下配置を再計算する。有効な位置がまだないときは非表示にする。変換終了、フォーカス変更、入力不可などで候補を隠す際には記録した位置も破棄し、次の変換へ持ち越さない。位置取得が回復したら新しい位置を使う。空の位置情報も取得不能として扱う。

既存の9件ごとの表示と選択、入力フォーカス、上下切替、画面内への配置を維持する。表示件数の変更は今回の対象に含めない。位置取得失敗、候補の増減、打鍵表示の有無、初回失敗、非表示後の失敗、取得回復を再現テストで確認し、修正前の失敗と修正後の通過を記録する。

このPCへの適用は利用者から依頼済み。標準パッケージ試験、版番号の一致、辞書・設定の退避を行い、標準アップデータをジョブから独立して起動する。適用後は登録DLLと配布ファイル、導入DLLの候補試験、brokerの独立稼働を確認する。外部公開は行わない。

検証・適用結果: 再現試験は修正前の30pxで失敗し、修正後の222pxで通過。標準パッケージのNative18/18、Microsoft2/2、Google15/15と実TSF関連試験が通過した。候補表示DLL以外の6ファイルは従来の導入済みバイナリーを使用した。2026年10月17日02:54JSTに2.0.1-rc.6を適用し、登録DLL・manifest7/7・設定3/3・バックアップ11/11、導入済みDLLの候補試験、更新元終了後のbrokerのジョブ外稼働とモデルの正常応答を確認。元の発生アプリでの再発有無は未確認。詳細はdocs/CURRENT_STATE.mdとexperimental-build/candidate-layout-applied.json。
