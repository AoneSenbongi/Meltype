# 本家Meltypeの朝監視

2026年10月11日の利用者の依頼により、本家yksr-melt/Meltypeを毎朝9時、日本時間で確認する。監視はgpt-6-luna、更新の取り込みと検証はgpt-6.1-solが担当する。利用者はモデルを固定するための独立した定期タスクの作成と、更新時の委任を明示的に承認した。

対象はE:/prog/Meltype/WindowsのWindows Native版。Androidはこの監視では変更しない。通常Releaseと既定ブランチのコミットをGitHubのAPIで確認する。取り込み済みの基準はv1.2.1、47ace1428e5d4c9213f64dbbaf00d73a01386c69。2026年10月11日の初回確認では、本家の最新通常Releaseとmainの先頭コミットもこの基準と一致した。

監視状態はLOCALAPPDATA/MeltypeUpstreamMonitor/state.jsonへ保存する。確認日時、最後に観測したReleaseとコミット、取り込み・検証済みの基準、未処理の更新、依頼中の状態、検証結果の参照先を分ける。取得に失敗した場合は観測値を進めない。取り込みに失敗した場合は検証済みの基準を進めない。

LunaはAGENTS.md、docs/CURRENT_STATE.md、本書、監視状態を先に読む。Releaseとコミットが観測済みの値に一致し、未処理の更新がなければ終了する。新しい更新は差分を整理し、gpt-6.1-solのサブエージェントへ委任する。新しいReleaseに既存のコミットだけが付けられた場合は、コード差分を確認して重複取り込みを避ける。依頼中の更新を二重に起動しない。

6.1 Solは本家の変更を確認し、既存のMicrosoft／Google切り替え、本家アイコン、自動／英語モード、画面端の候補配置、Googleの辞書・履歴、検索対応、句読点と学習停止を保持する。必要な資料を先に更新し、不具合の修正では再現テストを先に追加する。関連する回帰試験とビルドを行い、必要な配布候補をローカルで準備する。版番号は既存の公開予定と候補番号の規則に従って決める。

監視担当は製品実装を変更しない。未コミットの利用者の変更や進行中の作業と競合する場合は、上書きせず判断を求める。状態資料の他作業の記録も保持する。サブエージェントの完了待ちはイベントで行い、短い間隔で確認しない。

このPCへの適用は検証後にバックアップを取り、登録版・配置ファイル・起動・辞書と設定の保持を確認する。最新の利用者指定AGENTS.mdにより、GitHubへの公開には今回の内容への確認が必要。公開先、版番号、タイトル・本文、変更点、検証、制限、セットアップEXEとSHA-256を準備して提示し、承認後にpushと新規タグ・Releaseの公開を行う。過去の包括的な公開許可を今回の確認として扱わない。公開済み配布物の差し替えとforce pushは行わない。

リリース文は既存の本文の版番号と本家番号の更新を基本とする。機能・検証・制限が変わった場合は、古い説明が残らないよう必要な箇所だけ修正する。Windowsの管理者確認は回避しない。取り消し、適用失敗、検証失敗では公開せず、既存の復旧手順に従って報告する。完了した工程と未完了の工程を区別して状態へ保存する。

変更なしの定例通知は行わず、新しい更新、更新候補の準備完了、取得・検証の失敗、判断が必要な問題だけ報告する。この定期タスクはローカルで動くため、実行時はPCを起動し、Codexアプリを動かしておく必要がある。

Meltype側の改修は不要。管理画面の「最新版を確認」は、このForkの通常ReleaseとセットアップEXE・SHA-256を確認する既存の方式を使う。本家の監視、Forkの更新準備、利用者への配布と導入は別の工程として扱う。
