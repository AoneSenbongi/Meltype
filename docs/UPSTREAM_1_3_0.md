# 本家1.3.0対応と独自2.0.0

## 要求と範囲

2026年10月19日、利用者が本家1.3.0正式公開を連絡した。前の指示に従い、正式版の共通変換処理・辞書・関連試験を取り込み、括弧内カーソル移動の不具合を修正する。独自Google/Microsoft変換、文脈モデル、英語文節の境界変更、句読点、全角空白、辞書・学習履歴を維持する。子音略入力は有効化しない。日英文脈学習の接続は検証してから判断する。

本家タグv1.3.0は6310c44。既存取り込み基準はv1.2.2-pre.2（21fb255）。本家のキーフック/TIP、OS別パッケージ、公式Webサイトは独自Native IMEへ置き換えない。残っている従来Windows本体のAPI削除は独自ビルドへの影響を確認し、必要なAPIは保持する。

## 作業の保全

利用者の追加指定により、ブランドアイコンを本家1.3.0の雪の結晶＋Mへ更新する。本家タグのnative/tip/meltype.icoをそのまま使用し、従来のロゴ画像の切り抜きを廃止する。Native DLLの登録アイコン、管理画面・トレイ、管理ランチャーとショートカット、セットアップEXEへ同じアイコンを反映する。自動／英語を区別するモード文字は維持する。各埋め込みリソースと元ICOの一致、描画とモード切替を検証する。

context-evaluationの通常インデックスとHEADを変更せず、現行追跡対象・未追跡ソースを一時インデックスからローカルコミット4e9e3afへ保全し、この専用作業先へ展開した。元作業先の未コミット内容を保持する。外部公開なし。

## 未解決と検証条件

利用者はCodexと管理画面で括弧内移動が動かないと報告。開始時の実設定CursorIntoBracketsとFullWidthParenthesesはともにtrue。旧試験はJISの「」だけを扱っており、実アプリでの()・（）を保証しない。実際にロードしたDLL、Shift付きの括弧入力、確定処理とTSFの選択位置を調べ、再現試験を修正前に追加する。

単体回帰とNative/Google/Microsoft、TSF・設定保存・個人データ保持を検証する。版番号は利用者指定どおり2.0.0、本家基準表示を1.3.0へ更新する。配布物・変更点・検証結果・制限をそろえ、公開前に具体的な内容の確認を受ける。

## 結果

共通コアと既存Windows本体の回帰637/637、標準パッケージ試験が通過した。括弧移動は共通コアの()・（）試験2/2に加え、TSF文書の確定終了通知でアプリが選択位置を戻す条件を追加したところ旧実装で失敗した。確定した範囲を保持し、終了通知後の別編集セッションで括弧内を選択する変更で通過。通常の確定処理は維持する。後続の移動編集が拒否されても、既に確定したEnterは再送しない。実際のCodex・管理画面の不具合と同じ原因かは未確認。

独自Windows本体が参照するため、AutoSwitch/両方判定など旧APIとその試験は残す。独自Nativeの管理画面には公開しない。共通コアの英字社名予測APIと既定OFFの設定は追加したが、Nativeへの追加機能接続は今回行わない。子音略入力・日英文脈学習の既存OFFを維持する。

2026年10月20日の追加指定により、公開SetupへzenzモデルとCPU runtimeを標準同梱する。開発用PC固有のEドライブ設定は使わず、相対パスの設定と全資産のハッシュを配布manifestに含め、既存の保護配置・起動・終了を使う。ライセンスと出典通知を同梱する。AVX2非対応CPUではモデルを起動せず通常のGoogle／Microsoft変換を維持する。仕様と検証はdocs/BUNDLED_ZENZ.md。

最終的に通常の矢印キー処理を使う修正f9cdc5eで実EDITの選択1/1を確認し、PC適用とEXE作成を完了した。利用者からも括弧内移動の成功報告を受領した（対象アプリは未特定）。以下は修正過程の記録であり、現在の不具合状態ではない。公開内容の承認待ち。成果物と検証結果はdocs/RELEASE_2_0_0.mdを参照。

## 実アプリでの再発（公開保留）

遅延対応0f4483eでも利用者が「まだ外側へ戻る」と報告し、管理画面が導入先package-25d45b69のDLLを読み込んでいることを確認した。待機時間を増やすだけでは解消しない。通常のWindows EDITコントロールと登録済みIMEを使う試験を追加し、ITextStoreACPを自作した既存試験との差を調査する。0f4483eの配布物も公開しない。

登録済みIME・通常のEDIT・通常のメッセージ処理で()→Enterを入力する試験を追加した。0f4483eでは全角括弧2文字の確定後にEM_GETSEL=2/2となり失敗を自動再現した。TSFのSetSelectionだけでは通常の入力欄に位置を保持できない。実アプリには通知後に通常の矢印キーを一度送り、入力欄自身に位置を更新させる方法を検証する。送信先が自プロセスの前面UIスレッドで、同じ文書にフォーカスがあり、選択が確定範囲内にある場合だけ実行する。修飾キーが押されている間は送らず、フォーカスや明示的な選択変更を尊重する。試験用文書の直接選択試験と、実EDITによる登録済みIMEの試験は区別して記録する。

利用者の再試験で「一瞬内側へ移動した後、外側へ戻る」と報告された。旧開発用管理画面を停止して導入先の管理画面をプロセスごと再起動し、新パッケージ1907f4e7のDLLをロードしたことを確認した後の報告である。直後の別編集セッションだけでは後続の選択位置通知に上書きされる。遅延通知の再現試験を追加し、メッセージ処理後の一度だけの移動に変更する。途中の新規入力・フォーカス変更・明示的な範囲選択を尊重し、確定済み文字は再挿入しない。作成済みEXE（ソース8b7cfa6）は公開しない。
